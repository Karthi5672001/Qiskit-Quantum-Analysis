Decoder Latency and Backlog Modelling¶

A fault-tolerant quantum computer generates syndrome information continuously. The classical decoder must process each syndrome record quickly enough to prevent an accumulating backlog.

This notebook models the decoder as a queueing system in which:

  • syndrome windows arrive at fixed intervals;
  • each window requires a variable amount of decoding time;
  • one or more classical workers process the queued windows;
  • a deadline is missed when decoding finishes later than the allowed response time.

The analysis distinguishes between:

  • batch throughput;
  • individual decoding latency;
  • queue stability;
  • tail latency;
  • backlog growth;
  • the number of parallel decoder workers required.

A decoder can have high batch throughput while still failing a strict real-time latency requirement.

Real-time decoder queue¶

Each syndrome window is treated as a job arriving at a classical decoder.

For a single decoder worker:

utilisation = mean service time / arrival interval

A system with utilisation below one may be stable, meaning that the backlog can return to zero. A system with utilisation above one receives work faster than it can process it, so its backlog grows over time.

Low mean utilisation is not sufficient to guarantee short response times. Variability and long-tail service times can still produce deadline misses and temporary backlogs.

def calculate_worker_utilisation(
    mean_service_time_microseconds,
    arrival_interval_microseconds,
    number_of_workers=1,
):
    """
    Calculate average utilisation per decoder worker.
    """

    if mean_service_time_microseconds <= 0:
        raise ValueError(
            "Mean service time must be positive."
        )

    if arrival_interval_microseconds <= 0:
        raise ValueError(
            "Arrival interval must be positive."
        )

    if number_of_workers <= 0:
        raise ValueError(
            "Number of workers must be positive."
        )

    return (
        mean_service_time_microseconds
        / arrival_interval_microseconds
        / number_of_workers
    )

def simulate_decoder_queue(
    service_times_microseconds,
    arrival_interval_microseconds,
    number_of_workers=1,
    deadline_microseconds=None,
):
    """
    Simulate deterministic job arrivals and variable
    decoder service times across parallel workers.

    Jobs are assigned to the worker that becomes
    available first.
    """

    service_times = np.asarray(
        service_times_microseconds,
        dtype=float,
    )

    if service_times.ndim != 1:
        raise ValueError(
            "Service times must be one-dimensional."
        )

    if np.any(service_times <= 0.0):
        raise ValueError(
            "All service times must be positive."
        )

    if arrival_interval_microseconds <= 0.0:
        raise ValueError(
            "Arrival interval must be positive."
        )

    if number_of_workers <= 0:
        raise ValueError(
            "Number of workers must be positive."
        )

    if deadline_microseconds is None:
        deadline_microseconds = (
            arrival_interval_microseconds
        )

    worker_available_times = np.zeros(
        number_of_workers,
        dtype=float,
    )

    number_of_jobs = len(
        service_times
    )

    arrival_times = (
        np.arange(
            number_of_jobs,
            dtype=float,
        )
        * arrival_interval_microseconds
    )

    start_times = np.empty(
        number_of_jobs,
        dtype=float,
    )

    completion_times = np.empty(
        number_of_jobs,
        dtype=float,
    )

    waiting_times = np.empty(
        number_of_jobs,
        dtype=float,
    )

    response_times = np.empty(
        number_of_jobs,
        dtype=float,
    )

    assigned_workers = np.empty(
        number_of_jobs,
        dtype=int,
    )

    for job_index in range(
        number_of_jobs
    ):
        worker_index = int(
            np.argmin(
                worker_available_times
            )
        )

        start_time = max(
            arrival_times[job_index],
            worker_available_times[
                worker_index
            ],
        )

        completion_time = (
            start_time
            + service_times[job_index]
        )

        waiting_time = (
            start_time
            - arrival_times[job_index]
        )

        response_time = (
            completion_time
            - arrival_times[job_index]
        )

        worker_available_times[
            worker_index
        ] = completion_time

        start_times[job_index] = (
            start_time
        )

        completion_times[job_index] = (
            completion_time
        )

        waiting_times[job_index] = (
            waiting_time
        )

        response_times[job_index] = (
            response_time
        )

        assigned_workers[job_index] = (
            worker_index
        )

def calculate_backlog_at_arrivals(
    queue_dataframe,
):
    """
    Calculate how many previously arrived jobs remain
    incomplete when each new job arrives.
    """

    arrival_times = queue_dataframe[
        "arrival_time_microseconds"
    ].to_numpy()

    completion_times = np.sort(
        queue_dataframe[
            "completion_time_microseconds"
        ].to_numpy()
    )

    completed_by_arrival = (
        np.searchsorted(
            completion_times,
            arrival_times,
            side="right",
        )
    )

    arrived_jobs = (
        np.arange(
            len(queue_dataframe)
        )
    )

    backlog = (
        arrived_jobs
        - completed_by_arrival
    )

    return np.maximum(
        backlog,
        0,
    )

Decoder latency and backlog results¶

The batch decoder achieved a substantially different time per shot from repeated single-shot calls. Batch decoding amortised Python and library-call overhead across many detector samples, while the single-shot benchmark exposed per-call overhead and operating-system variability.

The single-shot latency distribution contained a central region and a longer upper tail. Consequently, mean service time alone was not sufficient to characterise real-time behaviour. The 95th-, 99th- and 99.9th-percentile latencies provided additional information about unusually slow decoding jobs.

The relationship between detection-event count and decode latency was assessed using both Pearson and Spearman correlations. A positive association would indicate that denser detector samples tend to require more classical processing, although event geometry and matching-graph structure can also affect difficulty.

Queue utilisation was defined as the mean service time divided by the arrival interval and number of parallel workers. Configurations with utilisation above one were analytically unstable because syndrome jobs arrived faster than the decoder system could process them.

The discrete-event simulation demonstrated that an overloaded decoder developed a growing backlog and increasing response times. Adding parallel decoder workers reduced utilisation and could stabilise the queue, but stability did not guarantee that every job met a strict deadline.

Deadline misses were influenced by both average load and service-time variability. Even configurations with utilisation below one could miss short deadlines because of tail-latency events.

These results are measurements of PyMatching running through Python on the current CPU. They do not directly predict FPGA or ASIC decoder performance. However, the workflow identifies the quantities that specialised hardware must improve: mean service time, tail latency, sustainable throughput, communication overhead and concurrency.

A full quantum-classical architecture model should also include syndrome-transfer latency, data formatting, decoder output transmission, control-system response and any dependency between successive correction cycles.
